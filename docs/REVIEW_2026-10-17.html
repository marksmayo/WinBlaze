Coverage and limits

The remaining high-risk areas were reviewed by hand: window close and persistence, the native FFI boundary, scanner enumeration, search and import changes, and report rendering.
Fuzz testing
A new dependency-free mutation fuzzer, src/WinBlaze.Native/examples/fuzz_inputs.rs, ran 9 targets: CSV, TSV and JSON import, MFT records, MFT dump, the snapshot cache, the capacity hint, the update manifest, and search plus export filters. It fed 200,000 inputs per target (50,000 for the snapshot cache). There were no panics and no input took longer than 1 s. The MFT seed is synthetic, so coverage there is shallow; a real dump from an elevated --dump-mft would reach deeper.

Defects fixed

HighFixedData loss

Closing the window right after a scan discarded the scan's catalog

A finished GUI scan writes its catalog snapshot in the background. OnWindowClosed called TerminateProcess immediately and killed that write, so the next launch reopened the previous catalog. The CLI already waited for the write; the GUI didn't.

Fix
New export wb_wait_for_snapshot_writes (bridge.rs) takes the persist gate and then waits for terminal-scan writes. NativeBridge::WaitForSnapshotWrites calls it before the process ends, and skips the call if the engine was never loaded.
Tests
Red then green: snapshot_write_wait_blocks_until_the_persist_gate_is_released. End to end: scan 250k files, close as soon as results appear, relaunch. The catalog is restored, and closing took 55 ms.
MediumFixedUI correctness

Title named the wrong folder after restoring a saved catalog

After a launch that restored a catalog, the title read "WinBlaze - C:\" (the default in the path box) while it showed another folder's results.

Fix
When the loaded catalog's root differs from the current path (ignoring case and trailing backslashes), UpdateWindowTitle names the catalog root. Titles for ordinary scans are unchanged.
Tests
Red then green with the relaunch check: the title showed C:\ before the fix and the lognormal folder after it.
MediumFixedReport rendering

The benchmark report crashed when the data had no products field

report-template.html.template declared const PRODUCTS=DATA.products||PRODUCTS, which refers to itself and throws "Cannot access 'PRODUCTS' before initialization". Older baselines rendered through verify-best-report.mjs lack the field.

Fix
The fallback is now the three core products.
Tests
Red then green: new benchmarks/verify-template-products.mjs.
MediumFixedBroken tooling

Five benchmark scripts ran examples whose sources had been deleted

run-feature-comparison.ps1, run-elevated-native-comparison.ps1, run-mft-reopen-validation.ps1, verify-parity-interop.ps1 and inspect-empty-scale-process.ps1 run feature_catalog, feature_maintenance, ffi_scan_repro, scan_export and soak_repro. The earlier session deleted those sources.

Fix
Restored the five sources from main. All compile against the current APIs.
MediumFixedRace

A late text-change event erased the invalid-folder error

XAML raises TextChanged asynchronously, so the event for the text just validated could arrive after Start scan and reset the error. The Debug build lost this race every time.

Fix
The error is kept while the text is still the text that failed validation.
Tests
The path-ux.ps1 -Case invalid smoke test, which had been failing, now passes.
LowFixedRobustness

A poisoned per-session lock would abort the app

Five session mutex locks in bridge.rs used .expect("lock poisoned"). Some run inside the unguarded wb_scan_session_cancel and wb_scan_session_destroy, where a panic across the C ABI aborts the process.

Fix
These locks now recover the guard (PoisonError::into_inner), as the global model lock already did.
LowFixedTests and conventions

Gate and test hygiene

  • The UI smoke test reused a catalog from 11 October, which changed the window title. It now clears its app-data folder on each run.
  • The restored-window test sized the window in raw pixels, a 450×350 layout at 200% scaling. It now sizes in DIPs.
  • In capacity_hint.rs a test module sat in the middle of the file (clippy items_after_test_module).
  • The extension-list throttle member was written but never read; it's removed, and the extension list now rebuilds from a single path, which is traced.
  • The live extension totals now use one shared helper instead of a second lookup and a duplicated update block.
  • New lines in main.rs and csv_import.rs broke the CLAUDE.md 100-character limit; they're wrapped now.
