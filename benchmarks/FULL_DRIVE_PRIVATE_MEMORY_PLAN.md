# Standard-user full-drive private memory

Keep the existing C: startup + complete scan/index/persistence + CSV export workflow, standard-user token and n=10 for every product. Compare the median of sampled peak private bytes, in MiB. Preserve all observations; do not trim working sets, skip files or postpone work outside the measured process.

## Qualification order

1. Remove the tree builder's temporary per-file parent array. The existing directory lookup can resolve each parent during the counting and child-placement passes. Expected saving: four bytes per file during tree construction (about 6.6 MiB at 1.73 million files), subject to the measured process peak. Public tests must verify allocation, totals and child order; existing orphan/sparse-parent tests must remain green.
2. Investigate bounded growth of large file-record arenas and avoid shrinking when retained spare capacity already meets the existing 12.5% publication budget. A public transaction handoff test must prove that every record survives, capacity remains bounded and publication allocates no replacement record arena. More frequent growth may cost CPU, so retain full-drive timing and CPU measurements alongside memory.
3. Keep compact dense-ID lookup for early out-of-order worker batches. An arrival beginning at ID 1,537 exceeded the old initial allowance and permanently selected a sparse map. Permit a 16,384-ID initial allowance (64 KiB of slots), retaining the existing dynamic limit and sparse fallback. This trades bounded extra storage for small, moderately sparse catalogs against potentially much larger lookup savings on a full walk scan.

These are candidate savings, not achieved process-memory reductions. No interface or file-format changes are planned. Compact file timestamps, name interning, custom allocators and alternate physical-identity tables require broader compatibility work and are not treated as low-risk fixes here.

## Advisory count estimates

A compact versioned hint stores only counts keyed by requested root and scan rules. Successful complete directory-walk persistence updates it atomically. A matching next scan can reserve record/lookup capacity once, with 5% headroom; all directories and files are still enumerated, indexed, persisted and exported. No scan result is cached by this mechanism. Unknown/mismatched/corrupt hints fall back to ordinary growth. Raw MFT and incremental paths do not use the walk hint. The estimate is limited to 512 MiB of record/lookup storage, not total process memory. Large changes can make a stale estimate over-reserve temporarily; publication still enforces its existing retained-capacity budget.

Public round-trip, root isolation, budget and rule-isolation tests each have runtime RED/GREEN logs. Corruption/truncation guards pass. The real isolated native scan/export test first failed because no hint was saved, then passed with complete catalogs after adding files and with optional hint-write failure. Cold or unmatched-root first observations remain included in benchmark medians.
